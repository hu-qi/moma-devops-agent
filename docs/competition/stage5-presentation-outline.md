## 一、方案核心说明 (Executive Summary)

### 1. 行业痛点与用户画像

- **目标用户**：企业研发团队（央国企、政务金融机构、互联网研发中心）、DevOps/SRE 工程师、开源社区维护者。
- **三大行业痛点**：
  1. **代码生成易，生产交付难**：现有 AI 助手仅停留于“单次代码补全”，缺乏自动化编译测试、CI 流水线修复、规范 PR 发起的端到端工程闭环。
  2. **自写自审易生幻觉与越界风险**：传统 Agent 自主生成代码后往往“自己确认无误”，容易引入注入漏洞、越界逃逸与明文敏感数据泄漏。
  3. **异常中断导致状态不一致与死循环重试**：网络闪断、CI 频繁红灯时，缺乏原子租约管控，容易导致海量重复 PR 泛滥与模型 API 费用无底洞消耗。

### 2. 移动云 MoMA 平台价值赋能

- **Token 集约化运营与降本**：接入中国移动 MoMA 大模型平台，得益于国产算力部署、PD 异构分离与自研推理引擎优化，单位 Token 成本较直连压降约 **30%**，时延降低 **40%**（来源：新华网 2026-05-08 报道）。
- **统一 API 网关与丰富模型矩阵**：统一接入移动云自营“九天”大模型、DeepSeek 系列（R1 / V3 / V4.1-Flash）、通义千问系列（Qwen3-32B / Qwen2.5），支持普惠经济档与推理旗舰档无缝切换。
- **透明按量计费与体验保障**：完全基于移动云官方帮助中心（文档编号 91592，2026/09/23 更新）自营模型资费，每百万 Token 计费透明（Qwen3-32B 2元/百万 tokens，DeepSeek-V4.1-Flash 2元/百万 tokens），支持流式即用即付与 2500 万 Token 体验支持。

## 二、答辩演示文稿（PPT / Slide Deck）逐页结构设计 (12 页)

### Slide 1: 封面 (Title Slide)
- **主标题**：DevOpsPilot：基于移动云 MoMA 的自主演进端到端研发交付控制面
- **副标题**：中国移动“移动云杯”算网人工智能开发者大赛作品
- **呈现要素**：DevOpsPilot Logo、中国移动 MoMA 标志、团队名称、2026年9月。

### Slide 2: 痛点与破局：从“代码补全”到“可信自主交付”
- **核心观点**：代码生成的最后一公里不是写出代码，而是跨过安全门禁、通过 CI、完成合规审查。
- **对比图表**：
  | 维度 | 传统 AI 编程插件 (Copilot 类) | 实验性 Multi-Agent 框架 | DevOpsPilot 交付控制面 |
  |---|---|---|---|
  | **执行范围** | 仅单文件局部补全 | 容易发散失控、死循环 | 全生命周期闭环交付 (Issue→PR→CI) |
  | **审查机制** | 依赖人工肉眼盯防 | 自写自审、互相掩护 | **强制独立物理隔离 Reviewer** |
  | **异常恢复** | 无状态，断点重来 | 易产生重复 PR / 资源泄漏 | **意图租约 + 预算前置扣减** |
  | **模型成本** | 固定调用高价闭源模型 | 盲目堆叠 Agent 消耗翻倍 | **Single Agent First + MoMA 智能路由** |

### Slide 3: 核心理念一：Single Agent First 与普惠路由
- **核心观点**：不为“多智能体”而“多智能体”，以实际工程净收益为准绳。
- **设计逻辑**：
  - 常规修复与低风险任务：默认调用 Single Agent + 经济档模型（Qwen3-32B，2元/百万 tokens），控制响应时延与 Token 消耗。
  - 跨模块架构重构与高难度故障：动态调度 Agent Team（Architect + Coder + Reviewer）深度协同。
  - 无显著效益不推广 Team，把实实在在的降本带给企业。

### Slide 4: 核心理念二：强制独立代码审查硬门禁 (Enforced Independent Review)
- **核心观点**：杜绝“既当运动员又当裁判员”。
- **架构展示**：
  - Code Generator 与 Reviewer 在进程、上下文及角色权限上完全隔离。
  - Reviewer 输出类型化结果（`APPROVED` / `REJECTED`），审查结论必须与 Commit SHA / Tree Digest 原子绑定。
  - 只有取得有效 `APPROVED` 证书，平台适配器才被允许触发提交和开 PR。

### Slide 5: 核心理念三：意图租约控制与预算前置预留
- **核心观点**：生产级系统的底线是崩溃时不添乱、恢复时不重做。
- **机制剖析**：
  - **副作用前置锁定**：在调用 SCM API 创建 PR 之前，先在本地 SQLite 登记意图租约与分配 Attempt 计数。
  - **断点恢复 (Resume)**：遭遇中断或崩溃后，CLI `resume` 命令直接读取持久化状态，精确复用原有 PR 与分支。
  - **零副作用保证**：严格防范因重试导致的“PR 海啸”与模型账单超支。

### Slide 6: 核心理念四：行业合规包防逃逸与安全左移
- **核心观点**：政企代码不容明文泄露，合规检查必须嵌入流水线最前端。
- **实例演示**：
  - 政务审计合规包（`industry-packs/government`）：内置公民个人身份信息、敏感配置与未授权网络调用检查规则。
  - 路径白名单策略（`Path Policy`）：严格限制 Agent 的工作目录，防止跨目录读写与篡改关键配置。

### Slide 7: 系统总体技术架构 (Architecture Blueprint)
- **层次展示**：
  1. **接入层**：统一 CLI 入口、GitHub / AtomGit SCM 事件 Webhook 监听。
  2. **控制面 (Control Plane)**：基于 OpenJiuwen 引擎，集成意图识别、计划编排、状态机跟踪与持久化 SQLite 账本。
  3. **模型网关 (MoMA Gateway)**：统一调用中国移动自营模型，流式计量与透明计费。
  4. **门禁与验证层 (Quality & Security Gate)**：独立 Review 拦截、CI 失败同分支 RCA 修复、行业合规检查。
  5. **自演进层 (Governed Evolution)**：轨迹结构化采集、候选挖掘、离线回归评测、人工签署与版本回滚。

### Slide 8: 真实端到端交付演示与三条路径 (Live / Recorded / Deterministic)
- **展示内容**：
  - **Path A: Deterministic**（离线确定性执行，零凭据耗时 5 秒，41 项断言全绿）
  - **Path B: Recorded**（真实历史运行轨迹与完整证据快照查验）
  - **Path C: Live**（直连 GitHub 与 MoMA API，标准特性交付 + CI 翻绿）
- **一键演示指令**：`./scripts/run_demo.sh [mode]`

### Slide 9: 同题同预算消融评测体系 (DevOpsBench)
- **评测设计**：
  - **A0** (Single Fast / Qwen3-32B)
  - **A1** (Single Capable / DeepSeek-V4.1-Flash)
  - **A2** (Dynamic Single / 动态单 Agent)
  - **A3** (Agent Team / 协作团队)
- **评测纪律**：同题、同预算、同 RC、重复三次取分布；未核实价格一律记 `Unestimated`，杜绝伪造数据。
- **评测工具**：`runner.py sweep` 预估规模透明可见，`recompute_metrics.py` 严格复算指标。

### Slide 10: 受控自主演进闭环：拒绝黑盒失控
- **闭环链路**：真实交付轨迹 (Trajectory) → 提取通用 Skill 候选 (Candidate) → DevOpsBench 离线双向评测 → 收益门禁 (Gain Gate) → **强制冻结在 `PENDING_HUMAN`** → 专家数字签名 → 生产晋级。
- **安全保障**：负收益提案自动拦截，正收益提案绝不绕过人工自作主张，支持秒级一键版本回滚。

### Slide 11: 移动云商业化落地与行业推广价值
- **价值赋能**：
  - 面向省专公司与行业大客户，开箱即用的智能化研发提效底座。
  - 充分释放中国移动智算中心国产多芯算力与 MoMA 平台的集约化成本优势。
  - 符合金融、政务等关键领域“自主可控、数据不出域、审查有凭证”的安全合规硬性要求。

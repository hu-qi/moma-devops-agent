# DevOpsPilot 演示视频脚本与分镜规划 (C27)

> **时长规格**：3 分 30 秒 ～ 4 分 30 秒  
> **适用场景**：移动云杯 DevOpsPilot 决赛答辩 / 官方初审演示录屏 / 评审快速摸底

## 详细分镜与旁白解说词 (Detailed Storyboard)

### Scene 1: 痛点引言与架构定位 (0:00 - 0:45)

- **画面**：
  1. [0:00 - 0:15] 画面切入终端，背景为架构全景图（Control Plane、MoMA 智能模型网关、Multi-Platform Adapters、Industry Compliance Packs）。
  2. [0:15 - 0:45] 键盘键入 `./scripts/run_demo.sh deterministic`，终端瞬间打印出统一 CLI 的启动横幅，展示清晰的任务计划与模型分配决策。
- **旁白（语音解说词）**：
  > “各位评委老师好！当前市面上的 AI 研发助手往往停留在单次代码补全或聊天对话，面临三大落地痛点：缺乏生产级交付门禁、模型调用成本高昂不可控、遇到断点容易产生重复 PR 与副作用失控。  
  > 我们基于中国移动 MoMA 大模型平台，打造了 DevOpsPilot——面向研发自主演进的端到端自动化交付控制面。我们坚守三大工程纪律：第一，Single Agent First，低风险任务绝不滥用昂贵的多智能体；第二，强制独立 Reviewer 代码审查，杜绝自写自审；第三，意图租约与预算前置预留，彻底保障交付幂等与成本可控。”

---

### Scene 2: 标准特性自主交付与硬门禁拦截 (0:45 - 1:45)

- **画面**：
  1. [0:45 - 1:15] 演示终端分屏：左侧显示 Issue 需求分析，Leader 判定为低复杂度单模块特性，自动将模型路由至 MoMA 快速经济档 `Qwen3-32B`，进入 Single Agent 隔离工作区编码。
  2. [1:15 - 1:30] 编码完成后，触发独立安全 Reviewer。画面特写 Reviewer 检出边界错误并签署 `REJECT`，流程被硬门禁阻断，随后 Agent 自主二次重试并成功修复。
  3. [1:30 - 1:45] 最终生成真实 Commit SHA，自动在 GitHub/AtomGit 开启规范 Pull Request，状态原子流转至 `VERIFIED_CLEAN`。
- **旁白（语音解说词）**：
  > “现在大家看到的是特性交付全过程。控制面接入 Issue 后，自动进行复杂度分析。因为是标准特性，系统践行 Single Agent First，调度 MoMA 平台每百万 Token 仅 2 元的 Qwen3-32B 经济档执行。  
  > 值得注意的是，代码生成后绝不会直接合入，而是必须交由独立的 Reviewer 审查。在画面中我们可以看到，初次生成的越界风险被硬门禁立即阻断，直到 Agent 完成针对性修复并获得 APPROVED，才允许向仓库提交真实 Commit 并开启 PR。”

---

### Scene 3: 故障注入、同分支 RCA 修复与断点恢复 (1:45 - 2:45)

- **画面**：
  1. [1:45 - 2:10] 故障注入场景：特意引入一个导致 GitHub Actions / 单元测试红灯的用例。CI Webhook 触发后，DevOpsPilot 自动抓取 CI 失败日志，生成根因分析（RCA）报告，并在**同一个分支**上精准追加修复提交，实现红灯到绿灯的自动翻转。
  2. [2:10 - 2:35] 中断恢复场景：在 PR 开启后立即按下 `Ctrl+C` 人工强制掐断进程。随后运行 `devopspilot resume --delivery-id ...`。
  3. [2:35 - 2:45] 终端展示 SQLite Ledger 查询结果：状态平滑从断点恢复，直接复用既有 PR 与分支，重试预算计数器准确扣减，**没有产生多余的重复 PR 或垃圾提交**。
- **旁白（语音解说词）**：
  > “企业级交付最考验异常处置能力。我们现在注入一个 CI 失败故障。可以看到，系统并不重走全部流程，而是自动捕获报错日志、提炼 RCA，在原分支追加补丁，成功让 CI 翻绿。  
  > 更关键的是生产韧性。我们现在直接掐断进程模拟系统崩溃，再执行 resume 命令恢复。得益于控制面持久化的意图租约与 SQLite 账本，系统精准识别已打开的 PR，预算预留机制坚决杜绝死循环重试，真正做到零重复 PR、零状态泄露。”

---

### Scene 4: 行业合规门禁与受控自进化闭环 (2:45 - 3:45)

- **画面**：
  1. [2:45 - 3:15] 切换至政务行业审计场景（`industry-packs/government`）。Agent 在代码修改中尝试写入未脱敏的公民身份证号码。行业 Gate 立即阻断提交，控制台打出合规拦截证据，Agent 根据规范修正为合规脱敏函数。
  2. [3:15 - 3:45] 演示受控进化链路：执行 `governed-evolution-smoke`。系统从真实交付轨迹中挖掘出一条可复用的修复经验（Candidate），自动启动 DevOpsBench 离线回归对比。画面特写：负增益候选被自动 REJECT，正增益候选被严格冻结在 `PENDING_HUMAN`，直到管理人员执行人工签署后方可受控晋级，并保留一键回滚指令。
- **旁白（语音解说词）**：
  > “针对政企等严苛场景，DevOpsPilot 内置了行业合规包。在政务包演示中，任何明文敏感数据的引入都会被合规门禁当场阻断，实现安全左移。  
  > 在自主演进方面，我们坚决反对未经受控的‘黑盒自我修改’。系统从成功轨迹中沉淀出优化候选后，必须经由 Benchmark 双向对照。负收益提案自动拒绝；正收益提案必须严格停留在 PENDING_HUMAN 状态，唯有经过授权工程师的人工数字签名，才允许正式发布，且全流程支持原子回滚。”
